# 国际版与日版存档布局

v1.2.0 同时开放国际版及日版的初代 SRAM 布局，存档可以独立导入。ROM 哈希用于认证提示，不作为版本白名单。国际版红、蓝、黄的核心字段相同；日版红、绿、蓝、黄共用另一套布局，不能只做统一的地址平移。

## 字段对比

偏移从 32 KiB SRAM 文件开头计算。

| 字段 | 国际版 | 日版 |
| --- | --- | --- |
| 玩家名 | `0x2598`，11 字节 | `0x2598`，6 字节 |
| 昵称上限 | 10 编码字节 | 5 编码字节 |
| 背包 | `0x25C9`，20 组 | `0x25C4`，20 组 |
| PC 道具 | `0x27E6`，50 组 | `0x27DC`，50 组 |
| 随身队伍 | `0x2F2C`，6 只 | `0x2ED5`，6 只 |
| 当前精灵箱 | `0x30C0` | `0x302D` |
| 箱子 | 12 箱，每箱 20 只 | 8 箱，每箱 30 只 |
| 精灵记录 | 队伍 44、箱内 33 字节 | 相同，名字区长度不同 |
| 每箱字节数 | `0x462` | `0x566` |
| 箱存储区 | `0x4000`、`0x6000`，各 6 箱 | 相同起点，各 4 箱 |
| 对象显隐 | `0x2852` | `0x2848` |
| 地图工作区 | `0x289C` | `0x2892` |
| 剧情位起点 | `0x29F3` | `0x29E9` |
| 主校验位置 | `0x3523` | `0x3594` |

两者均从 `0x2598` 累加到主校验字节之前，再取反。日版使用单字节假名编码；法德与意西的重音字符也各有差异。程序分别处理名字长度、箱容量、字段偏移和相关校验。

字段事实对照：[PKHeX 的日版与国际版偏移](https://github.com/kwsch/PKHeX/blob/a5311f9f55a84376fd2e2499b25d9fb9640d9f2d/PKHeX.Core/Saves/Substructures/Gen12/SAV1Offsets.cs)、[初代箱容量与名字长度](https://github.com/kwsch/PKHeX/blob/master/PKHeX.Core/Saves/SAV1.cs)。实现独立编写，未引入其源代码。

## 地图事件与 ROM 的关系

存档记录事件位；地图对象和触发、战斗、奖励等逻辑来自 ROM。程序开放所有地图事件入口，已知关联可复位，其余可自定义关联或直接编辑剧情位。日版的对应区域使用日版基址，具体位含义和对象编号仍可能因版本而异，未确认的关联标为未认证。

能够读取 ROM 地图时显示实际图块及对象；没有 ROM 或尚未定位资料时显示参考定位图。认证提示不证明存档必然来自该 ROM。 [开放编辑与认证](开放编辑与认证.md)

## 维护方式

英文三版的历史游戏流程检查、法德意西红蓝版的历史基础检查保留在 [验收记录](验收.md)。本次日版和全部地图事件开放不追加兼容性或游戏流程测试，只执行编译、构建和发行包检查。后续根据 [用户反馈](https://github.com/LFK0560/PokemonRedSaveEditor/issues/new?template=compatibility.md)逐项修正规则和补充认证。
